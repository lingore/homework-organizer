# 作业文件批量整理工具（Homework Organizer）

一个用 **Python 标准库** 写成的命令行小脚本，用于批量整理作业文件：扫描列出、批量改名、归档分类、生成报告，并支持撤销。**不依赖任何第三方包**，Python 3.9+ 即可运行。

## 功能一览

| 子命令 | 作用 |
| --- | --- |
| `scan` | 扫描目录，列出文件（大小 / 修改时间），支持按扩展名过滤 |
| `rename` | 按规则批量改名（先打印预览、确认后才执行，自动处理重名冲突，绝不覆盖已有文件） |
| `archive` | 按学期 / 类别 / 扩展名把文件移动到子目录，并生成整理报告 |
| `report` | 查看整理报告（处理了多少、跳过多少、为什么跳过） |
| `undo` | 撤销上一次操作 |

## 安装

无需安装任何依赖，直接用系统 Python 运行：

```bash
python homework_organizer.py --help
```

## 快速开始

```bash
# 1. 扫描某目录，只看 PDF / Word
python homework_organizer.py scan ./作业 --ext .pdf .docx

# 2. 批量改名：学号_姓名_作业名.pdf → 作业名_学号.pdf（先预览，确认后才改）
python homework_organizer.py rename ./作业 --fields 3,1

# 3. 按学期归档到子目录，并生成整理报告
python homework_organizer.py archive ./作业 --by semester

# 4. 后悔了？撤销上一次操作
python homework_organizer.py undo ./作业
```

> 所有会改动文件的操作（`rename` / `archive` / `undo`）**都会先打印将要执行的动作清单，再询问确认**——只有输入 `y` / `yes` 才真正执行；直接回车、输入其他字符、EOF、`Ctrl+C` 一律视为取消，不会改动任何文件。

## 子命令详解

### 1. `scan` —— 扫描与列出

```bash
python homework_organizer.py scan <目录> [--ext .pdf .docx]
```

| 选项 | 说明 |
| --- | --- |
| `--ext .pdf .docx` | 只显示指定扩展名；写 `pdf` 或 `.pdf` 都可以，也支持 `--ext pdf,docx` 逗号写法，大小写不敏感 |

输出示例：

```text
扫描文件夹: /home/me/作业
扩展名过滤: .pdf .docx
符合条件: 2 个文件
----------------------------------------------------------------------
  20230101_张三_线性代数.pdf  |   512.3 KB  |  2025-03-01 10:20:31
  20230102_李四_大学物理.docx  |   128.0 KB  |  2025-03-02 09:05:12
----------------------------------------------------------------------
总计 640.3 KB
```

说明：目录不存在或不可读会报错退出（退出码 1）；个别文件因权限等原因无法读取时不会中断，只在末尾提示"另有 N 个文件无法读取"。整理日志文件不会被列出。

### 2. `rename` —— 批量改名

```bash
python homework_organizer.py rename <目录> [--split _] [--fields 3,1] [--ext .pdf]
```

按分隔符把文件名切成若干段，再按 `--fields` 指定的顺序重排，扩展名保持不变：

| 选项 | 说明 |
| --- | --- |
| `--split _` | 字段分隔符（默认 `_`） |
| `--fields 3,1` | 保留字段序号（从 1 数起）及顺序，默认 `3,1` |
| `--ext .pdf` | 只处理指定扩展名 |

例：`20230101_张三_线性代数.pdf` → `线性代数_20230101.pdf`。

**安全保证**：

1. 先打印「旧名 → 新名」预览清单，同时列出将要跳过的文件及原因；
2. 用 `input()` 等待确认，只有 `y` / `yes` 才执行，其余输入一律取消；
3. 重名冲突一律跳过、**绝不覆盖**——既防止撞上目录里已有的文件，也防止两个源文件改出同一个新名字；
4. 字段序号越界（比如文件名里没有那么多段）的文件单独跳过并说明原因，不影响其它文件。

### 3. `archive` —— 归档到子目录 + 报告

```bash
python homework_organizer.py archive <目录> [--by ext|semester|keyword] [--keyword-map "数学=Math;英语=English"]
```

| 选项 | 说明 |
| --- | --- |
| `--by ext` | 按扩展名分到 `pdf/` `docx/` 等子目录（默认） |
| `--by semester` | 按修改时间的学期分到 `2024-春/` `2024-秋/`（1–6 月为春、7–12 月为秋） |
| `--by keyword` | 按文件名关键词分到指定子目录，配合 `--keyword-map` 使用 |
| `--keyword-map "数学=Math;英语=English"` | 关键词映射表，分号分隔多条，`=` 左边是文件名里出现的关键词、右边是目标目录名 |

同样遵循「先预览 → 确认 → 才执行」；目标子目录里已存在同名文件时跳过，绝不覆盖。执行完会打印整理报告。

### 4. `report` —— 查看整理报告

```bash
python homework_organizer.py report <目录> [--all]
```

每次 `rename` / `archive` 都会把结果记录到该目录下的 `.organizer_log.json`。`report` 默认显示最近一次操作，`--all` 显示全部历史记录：**处理了多少、跳过多少、为什么跳过**。

### 5. `undo` —— 撤销上一次操作

```bash
python homework_organizer.py undo <目录>
```

把最近一次 `rename` / `archive` 的改动**原样还原**（把文件移回原来的位置），随后该条记录从日志中移除。可以连续执行，逐次往前回退。

- 还原前同样先打印清单并要求确认；
- 原位置已存在同名文件时跳过，绝不覆盖；
- 若个别文件还原失败（例如已被手动移走），会把这些条目保留在日志里，可以再次 `undo` 重试；
- 只把文件移回原位，不删除归档时创建的空子目录。

## 整理报告示例

```text
========================================================
整理报告
========================================================
操作 : archive
时间 : 2025-03-10 10:00:00
目录 : ./作业
--------------------------------------------------------
成功 : 12 个
跳过 : 3 个
合计 : 15 个
跳过原因：
  - 线性代数_20230101.pdf：重名冲突：pdf/线性代数_20230101.pdf
  - README.txt：无法确定类别
  - 未知文件.pdf：字段序号越界（'未知文件.pdf' 只有 1 段）
========================================================
```

## 设计原则

- **安全第一**：所有写操作都是「先预览 → 确认 → 才执行」，绝不静默改文件，绝不覆盖已有文件。
- **零依赖**：只用标准库，跨平台（Windows / macOS / Linux）。
- **可回退**：每次改动都写入本地日志 `.organizer_log.json`，`undo` 一键还原。
- **单项失败不影响整体**：某个文件读不了、改不了、移不了，只跳过它并记录原因，命令继续处理其余文件。

## 开发说明（3 个 PR）

本项目按三个需求拆分为 3 个分支，每个分支对应一个需求、各开一个 PR，保证每个 PR 的改动只包含该需求的内容：

| 分支 | 对应需求 | 合并到 |
| --- | --- | --- |
| `feature/1-scan` | 需求 1：扫描与列出（`scan`） | `main` |
| `feature/2-rename` | 需求 2：批量改名（`rename`） | `feature/1-scan` |
| `feature/3-archive` | 需求 3：归档与报告（`archive` / `report` / `undo`） | `feature/2-rename` |

> 合并顺序：按 1 → 2 → 3 依次合并；每合并一个 PR 后删除对应的 feature 分支，GitHub 会自动把下一个 PR 的目标分支指向 `main`，这样三个 PR 的 diff 始终各自对应一个需求。

主要提交历史（`git log --oneline`）：

```text
94e7dd9 feat(archive): 需求3 - 按学期/类别归档、生成整理报告、支持撤销上次操作
0ca2414 feat(rename): 需求2 - 批量改名，先预览确认后执行，重名冲突绝不覆盖
3cce451 feat(scan): 需求1 - 扫描目录列出文件，支持大小/修改时间与扩展名过滤
77ccd18 docs: 添加 MIT 许可证

```

## 推送到 GitHub 并创建 PR

```bash
# 1) 关联远程仓库
git remote add origin https://github.com/<你的用户名>/homework-organizer.git

# 2) 推送 main 与 3 个 feature 分支
git push -u origin main feature/1-scan feature/2-rename feature/3-archive
```

推送完成后，到 GitHub 网页上依次创建 3 个 PR（head / base 见上表），再按 1 → 2 → 3 的顺序合并。
